# speclint — архитектура

Черновик; контракты фиксируются в веху M0.

## Слои

```
адаптеры форматов  →  модель ядра  →  правила  →  отчёт (text | json)
(OpenSpec, позже       (требование,     (ссылки,
 Spec Kit, Kiro)        сценарий,        дельты,
                        решение,         решения,
адаптеры тестов    →    изменение,       покрытие)
(Kotlin/Java, TS,       ссылка, тест)
 Swift, Python)
                        манифесты зависимостей (M5)
```

- Правила видят только модель ядра и не знают формата файлов.
- Каждый документ модели знает свой корень и пространство имён — так несколько корней (M2) и внешние манифесты (M5) добавляются как источники данных без переделки правил.

## Адрес

`[пространство:]capability/requirement#scenario`

- Без пространства — локальный адрес текущего репозитория.
- С пространством — внешний; до M5 отмечается «не проверено», с M5 сверяется с манифестом.
- Как адрес строится из OpenSpec — вопрос Q1 в PLAN.md.

## CLI

По образцу Clear `req/cli`:

- коды возврата: `0` — чисто, `1` — есть находки, `2` — сломан запуск (неверные аргументы, нечитаемая конфигурация);
- `--format text|json`;
- JSON: `{tool, status: ok|findings, findings: [{level: error|warning|info, rule, file, line, message, related: []}], summary: {errors, warnings, files}}`;
- ID правил латинские и стабильные.

## Манифест (M5)

JSON, публикуется репозиторием на релизе: версия, требования, сценарии, решения со статусами, покрытие сценариев. Потребитель фиксирует версии зависимостей и сверяет внешние ссылки с манифестами без сети.
